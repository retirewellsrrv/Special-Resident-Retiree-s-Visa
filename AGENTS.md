# SRRV Service Platform — Agent Guide

## Quick Start

```bash
pnpm install
cp env.copy.example .env.local   # then fill in secrets
pnpm dev                          # http://localhost:3000
```

## Commands

| Command | Action |
|---|---|
| `pnpm dev` | Next.js dev server |
| `pnpm build` | Production build |
| `pnpm lint` | ESLint (next/core-web-vitals) |
| `pnpm test` | Vitest (watch mode) |
| `pnpm test:coverage` | Vitest with coverage report |
| `pnpm tsc --noEmit` | TypeScript check (not run in CI) |

CI runs `pnpm install --frozen-lockfile` → `pnpm test:coverage` → `pnpm build`.

## Stack

- **Framework**: Next.js 16 (App Router), React 19, TypeScript 5
- **Styling**: Tailwind CSS 3 + shadcn/ui (radix-nova style), CSS variables
- **Database**: Supabase PostgreSQL via `@supabase/ssr`
- **Auth**: Supabase Auth with role-based routing (applicant/admin/super_admin)
- **Validation**: Zod 4
- **Payments**: Xendit
- **Testing**: Vitest 2 + jsdom + `@testing-library/react`
- **Deploy**: Vercel via GitHub Actions on push to `main`

## Project Structure

- `src/app/(auth)/` — Public auth routes (login, register, forgot-password)
- `src/app/(admin)/` — Admin portal (role-gated layout)
- `src/app/(applicant)/` — Applicant portal (role-gated layout)
- `src/app/(super-admin)/` — Super admin routes (referenced by auth.ts, no directory present yet)
- `src/actions/` — Server Actions (application logic layer)
- `src/components/ui/` — **shadcn generated** — do not edit manually
- `src/components/shared/` — Components used by both portals
- `src/components/admin/` + `src/components/applicant/` — Portal-specific components
- `src/schemas/` — Zod schemas
- `src/hooks/` — TanStack Query hooks
- `src/types/supabase.ts` — **Auto-generated from Supabase** — never edit

## Key Conventions

- **Path alias**: `@/*` maps to `./src/*`
- **shadcn aliases**: `@/components`, `@/components/ui`, `@/lib`, `@/hooks`
- **Server Actions** are in `src/actions/`, named with `Action` suffix (e.g., `loginAction`)
- **Zod schemas** are in `src/schemas/`, validated in actions with `safeParse`
- **Tests mock** `next/navigation` `redirect()` to throw `'NEXT_REDIRECT'`
- **`revalidatePath` must run before `redirect`** in Server Actions
- **Do not rename migration files** — timestamps are auto-generated by Supabase CLI

## Environment Variables

Two keys for Supabase: `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` (public/anonymous) and `SUPABASE_SERVICE_ROLE_KEY` (admin bypass). The middleware also uses `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Copy `env.copy.example` and fill with real values.

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
SUPABASE_SERVICE_ROLE_KEY=
```

## Database Types

After any schema change, regenerate types:

```bash
supabase gen types typescript --project-id <id> > src/types/supabase.ts
```

`src/types/supabase.ts` must never be manually edited.

## Testing Notes

- Tests use `vi.mock()` for `@/lib/supabase/server` and `@/lib/supabase/client`
- Mock `next/navigation` `redirect` to throw `'NEXT_REDIRECT'` to test redirect paths
- Test files follow `**/*.{test,spec}.{ts,tsx}` pattern under `src/__tests__/`
- Setup file: `src/__tests__/setup.ts` (imports `@testing-library/jest-dom`)
